# Phase 14 — Restricted MultiPPI optimizer correction and reference-validation protocol

This is a targeted engineering fix prompted by the Phase 13 first-order gap audit. It is **not** a new generic simulation campaign, an official MultiPPI replication, a new theorem, or true harmful-response certification. No code is pushed and no research review email is sent.

## Included

- `phase11_reference_unmodified.py`: byte-for-byte retained original Phase 11 source, run only on **synthetic** outcomes and reviewer votes.
- `phase13_methods.py`: unchanged Phase 13 certificate and AM-PPI identity audit source.
- `phase14_certified_solver.py`: analytic-gradient SLSQP + Frank–Wolfe improvements; independently checks a convex objective first-order gap bound. If not within **0.5%**, the allocation is **not accepted** as certified.
- `phase14_targeted_paired.py`: compares original vs repaired restricted allocator on matched synthetic populations/seeds. Only reviewer active times are read from optional private SQLite DB (read-only). Runtime cost uses historical measured latencies with a **stated, unvalidated** GPU/human price ratio of 1.
- `phase14_finite_population_interval.py`: exact hypergeometric interval *only* for genuinely SRSWOR sampled allowed cases and a **qualified fixed reviewer-defined** outcome endpoint; not current real-case Y.
- `REFERENCE_VALIDATION_PROTOCOL.md`: operational sampling, blinding, adjudication, privacy, costs and claims thresholds.
- `test_phase14.py`, `test_phase14_reference.py`: local executable verification.

## Scientific novelty / fidelity boundary

Optimize Phase11's 7-subset covariance-GLS continuous objective with hard original `human_budget_fraction >= 0.12` constraint. This restricted pilot objective does not certify MultiPPI author's SOCP/SDP, reuse of burn-in, integer allocation, native model output, or published intervals. The first-order convex gap is a conservative objective-suboptimality **upper bound**, not an observed RMSE difference. Increasing numerical optimizer fidelity may leave empirical RMSE unchanged due to integer action rounding and sampling variability.

The `--db` flag, if present, reads exactly `ratings.active_seconds` (336 values) and no reviewer labels or texts. Synthetic Y, Z and predictors are freshly generated by the **old** Phase 11 simulator. The outputs are safe scalar aggregates only. Python dependencies: numpy, scipy; no pyarrow, model weights or GPU.

## Quick start

From extracted folder:

```bash
python3 -m unittest -q test_phase14.py test_phase14_reference.py

PY="$HOME/trustworthy-ai-monitor-fusion/.venv/bin/python"
DB="$PRIVATE_DIR/cases_private.sqlite"
OUT="$PRIVATE_DIR/phase14_certified_multi_20261113"

"$PY" phase14_targeted_paired.py --db "$DB" \
 --geometry development_1687 --populations 8 --repetitions 25 \
 --budget 4800 --tolerance .005 --out-dir "$OUT/development"

"$PY" phase14_targeted_paired.py --db "$DB" \
 --geometry phase6_5000 --populations 8 --repetitions 25 \
 --budget 4800 --tolerance .005 --out-dir "$OUT/phase6"
```

Outputs: each directory contains `phase14_aggregate.json` and `phase14_aggregate.md`; only **aggregate JSONs** should be uploaded here. Preexisting output directories are never overwritten.

The follow-on external qualified-reference validation **must use its own separately frozen sampling frame and labels**; do not claim it already happened.
